**What each pattern means ⭐:**
```
Failing at RESUME SHORTLIST
   → the resume or the keywords, not you. See ../03_Resume_and_Portfolio/00-Resume_Versions_Audit.md
     Check the (cid:) encoding issue and the visible-links issue first.

Failing at OA
   → speed and pattern recognition. See ../../06_Online_Assessments/
     Check: is it the coding or the aptitude/MCQ sections?

Failing at TECHNICAL R1
   → DSA execution under time pressure, or the protocol (coding before agreeing an approach).
     More mocks, not more problems. See ../01_Technical_Round_Prep/05-Mock_Interview_Log.md

Failing at TECHNICAL R2 / PROJECT ROUNDS
   → project explanation depth, or the question ladder (why × 3).
     See ../02_Project_Deep_Dives/00-How_To_Present_A_Project.md §3

Failing at HIRING MANAGER
   → fit, communication, or the narrative (the switch, the CGPA, the internship gap).
     See ../04_HR_and_Behavioral/

Failing at HR
   → rare, and almost always the difficult questions or an answer that sounded rehearsed.
     See ../04_HR_and_Behavioral/03-Difficult_Questions.md

CLEARING EVERYTHING BUT GETTING NO OFFER
   → you are competing well but not winning the comparison. Usually means the differentiator
     is not landing. For you that is the GPU + compilers combination — make sure it is
     stated early and concretely.  ⭐
```

## 7. The weekly review ⭐⭐

Fifteen minutes, every Sunday of the placement season:

```
□ Update the trackers above
□ Check: is every completed round debriefed? (Section 2, last column)
□ Look at Section 3 — has the failure stage changed?
□ Pick ONE action from the accumulated "three actions" lists and actually do it
□ Check which companies are coming up next week and read their files in
  ../../06_Online_Assessments/01_OA_Patterns_by_Company/
□ Re-read your own difficult-question answers if any are coming up
```

⚠️ **The failure mode of a tracker is that it becomes a record rather than a tool.** The weekly
review is what keeps it a tool.
