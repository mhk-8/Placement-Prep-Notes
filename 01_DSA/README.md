# 01 — Data Structures & Algorithms

> Folder: `01_DSA`

## Why this matters
The single highest-weight section. OAs are 2-4 coding problems in 60-90 minutes; interviews are 1-2 problems with follow-ups. Organise by pattern, because that is how problems are recognised under time pressure.

## Must-know checklist
- [ ] Recognise the pattern from the constraints before writing any code
- [ ] Derive time and space complexity out loud for every solution
- [ ] Write bug-free code on the first attempt for the 20 canonical problems
- [ ] Know the language's standard library cold (see `/03_Languages`)
- [ ] Handle edge cases by habit: empty, single element, duplicates, overflow, negatives

## Online-assessment angle
Constraints tell you the intended complexity: n<=20 → bitmask/backtracking; n<=1e3 → O(n^2); n<=1e5 → O(n log n); n<=1e7 → O(n). Read constraints first, always.

## Interview angle
Think aloud, state brute force, then optimise, then code, then dry-run on an example, then discuss complexity and edge cases.
